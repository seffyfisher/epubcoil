CSS ב־EPUB הוא חוזה גמיש: המו״ל מציע עיצוב, מערכת הקריאה מפרשת אותו, והקורא יכול לשנות גופן, גודל, שוליים ונושא. לכן המטרה אינה לשחזר דף מודפס בדיוק, אלא לשמור על היררכיה, קריאות וסדר גם אחרי שהטקסט זורם מחדש.

## מה אומר תקן EPUB על CSS

EPUB 3.3 תומך ב־CSS כפי שמוגדר בידי CSS Working Group Snapshot, ומוסיף רשימה מצומצמת של מאפיינים בעלי הקידומת `-epub-` כדי לתת מענה עקבי לשפות ולמצבי כתיבה. המשמעות אינה שכל מנוע קורא כל מודול CSS חדש באותה מידה. תקן EPUB מגדיר את שפת הפרסום; כל קורא מממש אותה בקצב ובאילוצים שלו.

המאפיינים בעלי הקידומת שנשמרו בנספח E הם `-epub-text-orientation`, ‏`-epub-writing-mode`, ‏`-epub-text-combine-horizontal`, ‏`-epub-text-combine`, ‏`-epub-hyphens`, ‏`-epub-line-break`, ‏`-epub-text-align-last`, ‏`-epub-word-break`, ‏`-epub-text-emphasis-color`, ‏`-epub-text-emphasis-position`, ‏`-epub-text-emphasis-style` ו־`-epub-text-underline-position`. אלה כלי תאימות לשימושים מסוימים, לא סיבה להקדים `-epub-` לכל כלל. השתמשו במאפיין CSS רגיל רק לאחר שבדקתם אותו בקורא היעד; אם צריך, הוסיפו את הצורה המוקדמת המתאימה. ההעמקה נמצאת ב־[קידומות EPUB](/css/epub-prefixes/).

CSS, גופנים ותמונות הם משאבי פרסום: יש לרשום אותם ב־manifest של [מסמך החבילה](/glossary/opf/) ולארוז אותם בתוך EPUB. קישור חיצוני ל־CSS או לגופן אינו בסיס אמין לקובץ שאמור לעבוד גם ללא רשת.

## הקורא מחזיק בהגה

קוראי EPUB רבים מאפשרים לקורא לבחור גופן, להגדיל טקסט, לשנות מרווחים, לבחור מצב בהיר או כהה ולפעמים לשנות שוליים ויישור. ההעדפות האלה חשובות לנגישות ולנוחות. stylesheet שמניח גודל מסך או גופן יחיד יישבר בדיוק כשקורא צריך להתאים אותו לצרכיו.

מכאן כמה החלטות פשוטות: השתמשו ב-`em` וב-`rem` לטקסט ולרווחים, השאירו גובה אוטומטי, ואל תבנו קומפוזיציה שדורשת מספר שורות קבוע. `px` מתאים לעתים לקו דק או למסגרת, אך לא כדאי לבסס עליו טיפוגרפיה של ספר זורם. המאמר [מלכודות קוראים](/css/reader-pitfalls/) מפרט מצבים שבהם override של המשתמש משנה את התוצאה.

## כללי יסוד לספר זורם

הימנעו מ-`position: fixed` וממיקום מוחלט של תוכן קריאה. הם יכולים להתנגש בטקסט אחרי הגדלת גופן, להתנתק מן העוגן או להיחתך. הימנעו גם מ-`height` קבוע לפסקאות, כותרות ותיבות: גובה הוא כמעט תמיד הנחה על מסך ועל גופן.

אל תייצרו רווחים באמצעות רצפי `&nbsp;`, שורות ריקות או padding עצום שמנסה לדמות עמוד מודפס. שוליים בין בלוקים שייכים בדרך כלל ל-`margin-block`. השתמשו במאפיינים לוגיים, כגון `margin-inline` ו-`padding-block`, כדי שהכלל יתאר התחלה, סוף ולפני/אחרי במקום שמאל וימין פיזיים. הדבר חשוב במיוחד לספר [RTL](/hebrew/rtl-basics/).

לתמונות קבעו גבול עליון לרוחב והשאירו את הגובה יחסי:

```css
img {
  display: block;
  max-inline-size: 100%;
  block-size: auto;
  margin-block: 1em;
  margin-inline: auto;
}
```

הכלל אינו מבטיח שכל קורא ימרכז באותה צורה, אך הוא מונע מתמונה לחרוג מרוחב אזור הקריאה. תמונה שהיא מידע זקוקה גם לטקסט חלופי ב־HTML; תמונה דקורטיבית יכולה לקבל `alt=""`. ראו [תמונות ב־EPUB](/design/images/).

## גופנים מוטמעים בלי לכפות אותם

אפשר להטמיע גופן ב־EPUB באמצעות `@font-face`, לכלול את הקובץ ב־manifest ולהפנות אליו באופן יחסי. בדקו רישיון הפצה והכלילו רק משקלים וסימנים שנדרשים. גופן עברי צריך לכלול ניקוד וסימנים אם הספר משתמש בהם.

```css
@font-face {
  font-family: "Book Hebrew";
  src: url("../fonts/book-hebrew.woff2") format("woff2");
  font-style: normal;
  font-weight: 400;
}

body {
  font-family: "Book Hebrew", serif;
}
```

הגדירו משפחת fallback הגיונית, ואל תסיקו שהגופן תמיד יופעל: מערכת קריאה או קורא עשויים להחליף אותו. הימנעו מ-`!important` בניסיון לנצח את העדפת המשתמש. הוא מקשה על תחזוקה ולעתים קרובות פוגע בהתאמות נגישות. לפרטים נוספים ראו [גופנים ו־CSS](/css/fonts-css/) ו־[גופנים עבריים](/hebrew/hebrew-fonts/).

## מעברי עמודים ואלמנות

פרק חדש הוא מקרה מתאים לשבירת עמוד. CSS המודרני משתמש במשפחת `break-*`; לקוראים ישנים כדאי להשאיר גם את השם הוותיק:

```css
h1.chapter {
  break-before: page;
  page-break-before: always;
  break-after: avoid;
  page-break-after: avoid;
}

p {
  orphans: 2;
  widows: 2;
}
```

`break-before` ו-`page-break-before` הם בקשה לקורא, לא מכונת דפוס. גם `widows` ו-`orphans` יכולים להיתמך באופן חלקי. כתבו אותם כשהם משפרים את התוצאה, אך בדקו שאין תלות בהם כדי להבין את הספר. בדקו כותרת בתחילת ובסוף מסך, וראו [מעברי עמוד](/css/page-breaks/).

## RTL, יישור ומקטעים מעורבים

כיוון השפה אינו משימת CSS. הגדירו `dir="rtl"` ותגי שפה ב־XHTML, ו־`page-progression-direction="rtl"` ב־spine. EPUB 3.3 אוסר במפורש על `direction` ועל `unicode-bidi` בכל גיליון סגנון, משום שמערכת קריאה יכולה לא לממש CSS או לכבות אותו. השתמשו ב־`text-align: start` במקום `right`, וב־`margin-inline-start` במקום `margin-right`. למקטע אנגלי משמעותי הוסיפו `dir="ltr"` ב־HTML, לא כלל CSS.

```html
<html xmlns="http://www.w3.org/1999/xhtml" xml:lang="he" lang="he" dir="rtl">
  <body>
    <p>מספר ההזמנה הוא <bdi dir="auto">AB-1234</bdi>.</p>
    <blockquote dir="ltr" lang="en">A quotation in English.</blockquote>
  </body>
</html>
```

```css
blockquote {
  margin-inline: 1.5em;
  padding-inline-start: 1em;
  border-inline-start: 0.2em solid currentColor;
}
```

`writing-mode` אינו דרוש לעברית אופקית. מספרים, URLs וקיצורים לטיניים עדיין דורשים בדיקה בהקשר אמיתי; עיינו ב־[מספרים ולטינית](/hebrew/bidi-numbers-latin/).

## media queries ומצב כהה

אפשר לכתוב media queries, כולל `prefers-color-scheme`, אך אין להניח שמערכת הקריאה חושפת את ערך המערכת או מאפשרת לכללים שלכם לגבור על ערכת הנושא שלה. מצב כהה של קורא עשוי להחליף צבעים כדי לשמור על ניגודיות. לכן הגדירו צבעים רק כשיש להם תפקיד תוכני, ובדקו קישורים, הדגשות ותמונות שקופות גם בהיפוך צבעים.

```css
@media (prefers-color-scheme: dark) {
  body { color: #eee; background: #111; }
}
```

הדוגמה חוקית כ־CSS, אבל היא fallback ולא הבטחה לתכונת מצב כהה. אל תשתמשו בה כדי להסתיר תוכן או לדרוש רקע מסוים. הרחבה: [media queries ומצב כהה](/css/media-queries-dark-mode/).

## stylesheet בסיסי לספר עברי

נקודת פתיחה זו בכוונה קטנה. היא אינה מחליפה את הגדרות ה־HTML וה־OPF, ואינה מנסה לנצח את הקורא:

```css
body {
  margin: 0;
  padding: 0;
  font-family: serif;
  line-height: 1.6;
  text-align: start;
}

h1, h2, h3 {
  font-family: sans-serif;
  line-height: 1.25;
  margin-block: 1.5em 0.6em;
}

p { margin-block: 0 0.85em; }

h1.chapter {
  break-before: page;
  page-break-before: always;
}

img {
  max-inline-size: 100%;
  block-size: auto;
}
```

הרחיבו רק בעקבות צורך תוכני: מחלקה לשירה, הערה, ציטוט או איור. ככל שה־selector קצר יותר והנכס פחות קשיח, קל יותר לקורא לשמור על ההעדפות שלו.

## מה לא לעשות

אל תעתיקו stylesheet של אתר למסמך EPUB בלי לצמצם אותו. איפוסים אגרסיביים, אנימציה, grids מורכבים, JavaScript ותלויות רשת אינם משפרים בדרך כלל ספר זורם. אל תשתמשו בטבלה לפריסה, באלפי `span` רק לעיצוב, או ברקע תמונה כדי להעביר מידע. אל תסתירו כותרת סמנטית רק מפני שהעיצוב אינו רוצה אותה.

גם תצוגה מושלמת בקורא אחד אינה ראיה לתאימות. EPUBCheck יכול למצוא בעיות אריזה ומבנה, אבל אינו מדמה כל מנוע CSS. קודם עברו ולידציה, אחר כך בדקו בקוראים ובגדלי מסך שונים, עם גופן ברירת מחדל ועם גופן מוחלף. זהו ההבדל בין קובץ תקין לקובץ שנוח לקרוא.

## סדר בדיקה מעשי

פתחו את הקובץ בקורא שולחני ובמכשיר נייד או קורא ייעודי, אם אלה קהלי היעד. בדקו תוכן עניינים, כותרות, פסקה ארוכה, ציטוט, רשימה, תמונה, הערת שוליים ופרק חדש. הגדילו והקטינו גופן, החליפו גופן אם הקורא מאפשר, עברו לנושא כהה ובדקו ספר עברי גם עם קטע אנגלי. לבסוף עברו על [בדיקת EPUB](/production/epubcheck/) ועל [בעיות קוראים](/hebrew/reader-issues/) ורשמו את שם הקורא וגרסתו לצד כל תקלה.

## מבנה קודם לעיצוב

CSS טוב אינו מתקן HTML לא סמנטי. כותרת היא `h1` או `h2`, פסקה היא `p`, רשימה היא `ol` או `ul`, וציטוט ארוך הוא `blockquote`. כשהמבנה נכון, אפשר לתת לכל רכיב עיצוב עדין והקורא עדיין מבין אותו גם אם ה־CSS שלו מצומצם או מוחלף. קוראי מסך, ניווט לפי כותרות וחיפוש מרוויחים מאותו מבנה.

אל תעטפו כל משפט ב-`span` כדי לשלוט בשבירת שורה. שינוי גודל הטקסט יהפוך את ההחלטה לחסרת משמעות. אם צריך טיפול טיפוגרפי למונח או לשירה, צרו מחלקה בעלת משמעות, למשל `class="poem"`, והחילו עליה מעט כללים. כך אפשר לאתר ולבדוק את הבחירה בקלות.

## selectors וירושה

העדיפו selectors קצרים: `p.note`, ‏`blockquote` או `.chapter-title`, ולא שרשרת עמוקה שתלויה בדיוק במבנה. EPUB עובר לעתים דרך כלי המרה שמוסיפים עטיפות; selector עמוק עלול להפסיק להתאים בלי שהספר ייכשל בוולידציה. ירושה מועילה במיוחד לגופן, צבע וכיוון, אבל בדקו שהחרגות מקומיות אינן נשארות על רכיבים פנימיים בטעות.

שמרו stylesheet אחד או מעט גיליונות ברורים במקום כללים מוכפלים בתוך כל XHTML. שינוי עתידי בגודל רווח או בטיפול בקישור יהיה אז עקבי. חריג מקומי בתוך `style` הוא לפעמים הכרחי, אך הוא צריך להיות החלטה מודעת ולא ברירת מחדל של כלי יצוא.

## קישורים, צבע וניגודיות

קישור צריך להישאר מובחן גם כאשר צבעי הקורא משתנים. קו תחתון או טיפול נוסף כמו `font-weight` יכולים לעזור, כל עוד אינם פוגעים בקריאות. אל תבנו משמעות על צבע בלבד, למשל "הקישורים האדומים הם הערות". בקורא כהה צבע מותאם אישית עשוי להיות מוחלף או להישאר בעל ניגודיות נמוכה.

```css
a {
  color: inherit;
  text-decoration: underline;
}
```

הכלל הזה מעדיף את צבע הטקסט של הקורא ושומר סימן חזותי לקישור. בדקו קישורים בקטע עברי ובקטע לטיני, מפני שקו תחתון ומרווחים נראים אחרת בגופנים שונים.

## טיפול בטבלאות ובתוכן רחב

טבלה רחבה היא אתגר במסך צר. לפני CSS, שאלו אם הטבלה באמת נדרשת או שאפשר לנסח נתונים כרשימה. כשצריך טבלה, שמרו על מספר עמודות קטן, הימנעו מרוחבים קשיחים והוסיפו כותרות `th` ברורות. אל תסתירו עמודות חיוניות באמצעות media query; קורא עם מסך קטן עדיין צריך לקבל את המידע.

קוד, כתובות ארוכות ומילים בלתי נשברות עלולים לחרוג מהמסך. בדקו אותם בגודל גופן גדול. אפשר לעצב קוד בלוקי באופן שמאפשר גלילה אופקית, אך אל תשתמשו בגלילה כדי להסתיר טקסט קריאה רגיל. החלטה זו שומרת את הספר שימושי גם בלי מחוות מדויקות.

## מתי להוסיף כלל מיוחד

הוסיפו כלל רק כשיש דוגמת תוכן ובדיקה שמצדיקות אותו. למשל, אם שירה צריכה לשמור שורות, אפשר להגדיר מחלקה ייעודית ולהעמיד אותה למבחן בהגדלת גופן; אם לא, כלל `white-space` עשוי לגרום לגלישה. אם עמוד שער דורש טיפול מיוחד, בדקו אותו בנפרד מהפרקים ואל תגרמו לכל `h1` להתנהג כעמוד שער.

הגישה הזו גם מצמצמת סיכונים בהמרה ל־Kindle או לקורא אחר. ככל שהקובץ משתמש בפחות הנחות על viewport ועל מנוע CSS, גדל הסיכוי שהמסר הטיפוגרפי ישרוד. המדד אינו מספר השורות ב־stylesheet, אלא כמה היטב הספר נשאר קריא כשהקורא משנה את התנאים.

## רשימת בדיקה לפני יצוא

עברו על הגיליון ושאלו לכל כלל אם הוא משפר תוכן ממשי או רק מחקה עמוד מודפס. ודאו שאין בו `direction` או `unicode-bidi`, ששניהם אסורים בגיליון CSS של EPUB 3.3. ודאו שכל משאב מקומי שמקושר מן הגיליון, כגון גופן או תמונה, נמצא בארכיון ורשום ב־manifest. אל תסתמכו על כתובת רשת שתהיה זמינה בזמן הקריאה.

פתחו מדגם שמכיל כותרת, פסקה ארוכה, רשימה, ציטוט, קישור, תמונה וטבלה קטנה. החליפו גודל גופן, נושא וגופן אם הקורא מאפשר, ובדקו עברית לצד URL או ציטוט באנגלית. תוצאה טובה בגודל ברירת המחדל אינה מספיקה לספר זורם. רשמו את שם הקורא וגרסתו ליד כל חריגה; כך אפשר להבחין בין כלל CSS בעייתי לבין בחירת משתמש או מגבלה של מנוע מסוים.

אם נדרש fallback, השאירו אותו קרוב לכלל המודרני והסבירו בהערת מקור מדוע הוא קיים. הסירו כללים שיצאו משימוש במקום לצבור תיקונים היסטוריים. גיליון קצר, סמנטי ומבוסס בדיקות קל יותר לתחזוקה ולהמרה מכל ספרייה של CSS שהועתקה מאתר.

כך העיצוב נשאר שירות לתוכן, גם כשהקורא משנה את תנאי הקריאה.
